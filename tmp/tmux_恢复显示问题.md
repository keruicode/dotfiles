## 2026-10-11：命令无输出的配置修正

已修正两处配置：关闭 shell 的 Ctrl+s 输出暂停功能；把 Ctrl+s R 改为真正的整屏重绘，原来只刷新状态栏。当前空闲 shell 和快捷键已生效，隔离终端测试通过。

下次遇到无输出，先按 Ctrl+q，再按 Ctrl+s、Shift+r。此次未捕获异常现场，因此尚不能确认唯一原因；如果仍复现，保留现场并告知窗口名，便于进一步判断是否为 WezTerm 渲染问题。

## 2026-10-04：LaTeX 面板鼠标乱码已修复

原因确认：LaTeX 左侧已回到 zsh，却残留全屏程序的鼠标上报模式，鼠标移动因此变成 `35;50;20M` 等输入。

已清除该面板的残留模式和乱码，并增加每次返回 shell 提示符时的自动清理，当前面板已生效。没有重启 tmux，也没中断旁边的 Yazi 或 Codex。

隔离测试通过，正常全屏程序的鼠标功能不受影响。现在可以直接在原面板继续操作。

## 2026-09-29：鼠标事件混入 shell，终端状态未恢复

**这不是主题或字体问题，也不只是历史画面残影，而是终端状态没有正确恢复。**

我检查了对应的“云雷达”面板：

| 检查项 | 异常面板 | 正常 shell 面板 |
|---|---|---|
| 当前进程 | 只有 Zsh，没有 Yazi | Zsh |
| 鼠标全事件上报 | 仍开启 | 关闭 |
| 备用屏幕 | 仍开启 | 关闭 |
| 输出换行处理 | 关闭（`-opost`） | 开启 |

因此，图里的现象可以对应起来：

- **`M39;30;7…`**：与鼠标上报序列的残片吻合，坐标数据落进了 shell 输入。SGR 鼠标协议本身就使用分号分隔数字，以 `M/m` 结尾。[协议说明](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Mouse-Tracking)
- **`command not found: 6myazi`**：残留字符与 `yazi` 命令混在一起，被 Zsh 当成命令执行；不是 Yazi 没安装。
- **文字阶梯状错位**：输出换行处理异常，与当前查到的 `-opost` 一致。

**代码里有两个值得修的风险点：**

1. Resurrect 会恢复 Yazi，SR 的切换/聚焦钩子也会自动输入 `yazi`；恢复期间没有统一屏蔽后者，存在竞争风险。
2. 当前停止 Yazi 的流程只等进程退出，没有验证鼠标模式、备用屏幕和终端属性是否恢复；自动输入命令也没有确认输入行是干净的。

这两点能解释问题如何发生，但还没有复现并锁定本次故障的最初触发顺序。

建议修复顺序是：**恢复期间暂停 SR 自动启动 → 每个面板只启动一次 Yazi → 回到空闲 shell 时校验并恢复终端状态。** 不需要重建所有 session，也不应为了清屏删除历史快照。

本轮只做分析，没有重置面板或修改运行配置。当前乱码输入行不要直接按回车执行。
